## 1. Shared `common/` Specs and Config

Create a `common/specs/` directory containing shared, language-agnostic configuration and spec docs:

- `common/specs/journeys.yaml`
  - Defines a few example journeys (e.g. `view-account-details`, `login-and-view-dashboard`).
  - Each journey includes:
    - `id`, `name`, `description`
    - `preconditions`
    - `steps`
- `common/specs/selectors.md`
  - Describes the **selector policy** used by both JS and Python code.
  - Strongly prefer:
    - `getByRole` + accessible name
    - `getByLabel`
    - `getByTestId` (`data-testid` / `data-qa`)
  - Avoid:
    - brittle CSS classes
    - nth-child / layout-based selectors
    - deep descendant chains
- `common/specs/testing-philosophy.md`
  - Short doc describing:
    - “journeys” vs low-level tests
    - how resilience is achieved (selectors, timeouts, retriable patterns)
    - separation between spec (YAML/Markdown) and implementation (JS/PY)

These files are consumed conceptually by both JS and Python implementations; the MCP servers should expose them as resources.
